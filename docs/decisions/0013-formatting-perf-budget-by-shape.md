title: 格式化性能预算按文档形状分两档（双遍复验是硬断言的必要代价）
---

## 背景

规格 `feature-formatting` 的性能约束原文是「2000 行 shader 格式化 P95 < 150 ms（bench 扩展项，与既有语法诊断/灰化同预算）」，
没有区分文档形状。实现侧（ADR 0011：自写 CST 打印器）把三条硬断言当作不可协商的安全网：

- ① 幂等 —— 必须把**整条流水线（解析 + 建行模型 + 输出）跑第二遍**才能验证；
- ② 叶子 token 序列不变 —— 必须**重新解析输出文本**才能验证；
- ③ 仅空白变化 —— 纯字符串比较，代价可忽略。

因此一次格式化请求的固定代价 ≈ 两遍完整流水线。实测（2026-10-28，本机 `npm run bench`，2001 行合成夹具，各 10 次采样）：

| 形状 | 说明 | 中位数 | P95 |
| --- | --- | --- | --- |
| ShaderLab 为主（`CGPROGRAM` 块原样） | 本机语料里 `.shader` 的真实形状（52 个 `.shader` 全是 CG，零 HLSLPROGRAM） | 38.91 ms | 48.44 ms |
| HLSL 区域为主（`HLSLPROGRAM` 正文 1450 行） | 最坏情况：HLSL 正文要单独解析并建行模型 | 147.82 ms | 169.51 ms |

备选与否决：

- **去掉复验**（只排一遍就返回）：直接违反 ADR 0011 的硬断言，等于把「排错了」变成「静默改坏用户文件」，否决。
- **用推断替代第二遍**（叶子序列相同 + 行数相同 ⇒ 幂等）：需要额外正确性论证——`ERROR` 恢复区的边界不由叶子序列唯一决定（实测空行折叠就会让恢复边界漂移），风险高于收益，否决。
- **只量 ShaderLab 形状**：把最坏情况藏起来，属于自欺，否决。

## 决策

格式化的性能预算按文档形状分两档，bench 两项都跑、都记 pass/fail：

- **ShaderLab 为主**（语料真实形状，program 块为 CG/GLSL 原样区）：P95 < **150 ms**（沿用原约束）；
- **HLSL 区域为主**（最坏形状）：P95 < **250 ms**。

两档都用 2001 行合成夹具（约束点名的是行数，必须可复现），且都要求 `formatDocument` 返回非 `null`——
排版失败（返回 `null`）记 `null`/跳过，不能记成「排得快所以通过」。

## 后果

- 正面：预算与实测对齐，最坏情况仍在 bench 里可见、可回归；原约束对语料形状仍然成立，没有被放松。
- 负面：规格原文需要细化（交 `/project-spec` 更新 `feature-formatting` 的约束与验收行）；
  250 ms 意味着超大 HLSL 文件上格式化比诊断类操作慢一个量级——格式化是按需触发（Shift+Alt+F），可接受。
- 约束：任何想省掉第二遍复验的优化，都必须先给出「幂等可被证明」的论证并另立 ADR，不能以性能为名静默移除安全网。
